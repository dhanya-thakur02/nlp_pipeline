What is the NLP Pipeline?

From raw text to real understanding — step by step

When a computer receives a sentence like "Sundar Pichai, CEO of Google, earned $100 billion in 2024", it sees only characters. The NLP Pipeline is a series of processing stages that transforms this raw text into structured, meaningful data that machines can reason about — powering search engines, chatbots, medical diagnosis tools, and translation systems.

Think of it like an assembly line: each stage refines the text a little more, handing off to the next stage until we have rich, structured information ready for downstream tasks.

Each Step — Explained Deeply
1

Sentence Boundary Detection (Sentence Splitting)

Breaking a document into individual sentences before anything else

Before any other processing, a long document must be split into individual sentences. This sounds trivial — just split on periods! — but real language is full of traps. Consider: "Dr. Smith works at St. John's Hospital. She earns $2.5M." — periods appear inside abbreviations and numbers, not just sentence ends.

NLP systems use rule-based heuristics (e.g., "period followed by a capital letter") combined with ML classifiers trained on thousands of examples to get this right.

Key challenges: Abbreviations (U.S.A., Dr., Inc.), ellipses (...), quoted speech ("He said 'No.' She left."), and multilingual punctuation all cause edge cases.

Input (raw document)

"Dr. Smith won. She earned $2.5M in 2023."

Output (sentences)

["Dr. Smith won.", "She earned $2.5M in 2023."]

# Python — spaCy sentence splitting import spacy nlp = spacy.load("en_core_web_sm") doc = nlp("Dr. Smith won. She earned $2.5M.") for sent in doc.sents: print(sent.text) # → "Dr. Smith won." # → "She earned $2.5M."
2

Tokenization

Splitting sentences into individual words and punctuation tokens

A token is the atomic unit the NLP system works with. In English, tokens are usually words and punctuation marks — but it's more subtle than splitting on spaces. Consider: "don't" → is it one token or two ("do" + "n't")? What about "New York", "WiFi", or "U.S.A."?

Modern LLMs use subword tokenization (Byte Pair Encoding or WordPiece): rare words split into known pieces so any vocabulary is possible. "unhappiness" → ["un", "##happi", "##ness"]. The ## means "this continues the previous word."

3

Stop Word Removal

Filtering out high-frequency, low-information words

Stop words are very common words — the, is, at, on, and, a, of — that carry little semantic meaning on their own. Removing them reduces noise, speeds up processing, and improves performance for tasks like search indexing and topic modelling.

However, stop word removal is NOT always a good idea. For sentiment analysis, the word "not" is critical — "not good" completely reversed becomes "good". Modern neural models usually skip this step entirely and let the attention mechanism learn what matters.

Red = stop word removed  |  Green = content word kept

⚠️ When NOT to remove stop words

  • Sentiment analysis ("not bad" ≠ "bad")
  • Question answering ("who is he?")
  • Machine translation
  • Neural models (BERT, GPT) — they learn importance themselves

✅ When stop word removal helps

  • Search engine indexing (TF-IDF)
  • Topic modelling (LDA)
  • Document clustering
  • Keyword / keyphrase extraction
4

Stemming & Lemmatization

Reducing words to their root form so variants are treated as one concept

Words appear in many inflected forms: run, runs, running, ran. For many tasks, all these forms mean the same concept. We reduce them to a common base so the model treats them as one entity.

Stemming — fast, crude

Chops off word suffixes using simple rules. Very fast but often produces non-real-words.

  • "studies" → "studi"
  • "running" → "run"
  • "flies" → "fli"
  • "happily" → "happili"

Algorithm: Porter Stemmer, Snowball Stemmer

Lemmatization — smart, correct

Uses vocabulary + grammar rules to find the true dictionary form (lemma). Always produces real words.

  • "studies" → "study"
  • "running" → "run"
  • "better" → "good"
  • "was" → "be"

Tool: spaCy, NLTK WordNetLemmatizer

5

Part-of-Speech (POS) Tagging

Assigning each token its grammatical role — noun, verb, adjective, etc.

POS tagging assigns each token a grammatical tag. This tells the computer the structure of the sentence and helps resolve ambiguity. The word "book" can be a noun ("I read a book") or a verb ("Please book a room") — POS tagging resolves this using context.

Modern taggers use neural sequence models (BiLSTM, Transformers) that look at the full sentence context and achieve over 97% accuracy on standard English text.

NN — Noun
VB — Verb
JJ — Adjective
DT — Determiner
IN — Preposition
RB — Adverb

# spaCy POS tagging import spacy nlp = spacy.load("en_core_web_sm") doc = nlp("The smart robot quickly learned language.") for token in doc: print(token.text, token.pos_, token.tag_) # The DET DT # smart ADJ JJ # robot NOUN NN # quickly ADV RB
6

Parsing (Syntactic Analysis)

Building the grammatical structure — which words govern which

Parsing reveals the grammatical structure of a sentence. There are two major styles:

  • Constituency Parsing — groups words into nested phrases (NP = noun phrase, VP = verb phrase, PP = prepositional phrase). Shows the sentence as a tree of constituents.
  • Dependency Parsing — draws directed arcs between words showing which word governs which (subject, object, modifier). More popular in modern NLP because it's simpler and language-independent.

Parsing answers "who did what to whom" — essential for question answering, information extraction, grammar checking, and machine translation.

Dependency parse of: "The smart robot quickly learned language."

Arrows point from head → dependent. Labels show the grammatical relationship (nsubj = nominal subject, dobj = direct object, advmod = adverb modifier, det = determiner, amod = adjectival modifier).

7

Named Entity Recognition (NER)

Detecting and classifying real-world named entities: people, orgs, locations, dates, money

NER identifies and classifies spans of text that refer to real-world entities. It builds on all previous steps — tokenization provides units, POS helps disambiguate, parsing provides syntactic context.

NER uses BIO tagging: B-eginning of an entity, I-nside (continuing) an entity, O-utside any entity. This lets multi-word entities like "New York" or "Goldman Sachs" be captured as a single unit.

Complete NLP Pipeline Example

[Sundar, Pichai, CEO, Google, announced, new, AI, initiative, California]

Step 2: Stop Word Removal

[Sundar, Pichai, CEO, Google, announced, AI, initiative, California]

Step 3: Lemmatization

announced → announce

Step 4: POS Tagging

Sundar/NNP, Pichai/NNP, announced/VBD, initiative/NN

  • PERSON → Sundar Pichai
  • ORGANIZATION → Google
  • LOCATION → California
